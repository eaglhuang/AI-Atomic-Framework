# HIST-v2 設計稿 r3：已決定事項

狀態：**DRAFT。不是預先登記 v2.0，沒有凍結，沒有 run。** 外部審閱過 r2 之後，這份 r3 修正四項契約。在凍結之前不開凍結世代、不加 `SHA256SUMS`、不跑分類、不跑臂。

r2 的四項決定原樣帶過來。r3 另外記下外部審閱之後採用的契約。

| 編號 | 決定 |
|---|---|
| R2-D1 | 多於一個最佳共同祖先時，維持技術排除。理由碼 `multiple-best-common-bases`。排除列記下理由，並封存全部候選 SHA 與輸入身份。不私下挑一個 base |
| R2-D2 | 「8」是第一次送出之後的 **8 次重試**。第一次送出是嘗試 0。合計最多 **9 次嘗試**。30 秒從第一次送出起算，重試不把時鐘歸零 |
| R2-D3 | 內部重新合成若做成另一次提交嘗試，計入那 8 次。同一次合成裡單次 `git merge-file`、同一次原子替換裡的單次 fsync，不另計 |
| R2-D4 | 專案留出集加上 flask 與 requests。主跑 **2 個 seed**。2 個 seed 只是有限重播，不是可重現性證明 |
| R3-D1 | 主比較只留一條文字合併臂 `textual_merge_file`，不再把 occ 與 git_three_way 分成兩條。r2 已讓兩者使用同一把鎖、同一種原子替換、同一個 `git merge-file` 候選，沒有剩下可解釋的差別。file_lock 與 steward 仍是另外兩條 |
| R3-D2 | 功能交付率與「已接受變更的語意保留」分開。前者的母體是全部有單獨參考測試的 proposal，合法拒絕算進度成本、留在分母。後者只對實際接受的集合 S，對照 R(S)。合法拒絕、沒有測試、零分母各占一列 |
| R3-D3 | 全部觀察都是 0 時，bootstrap 百分位區間退化。零事件上界用單側 Clopper–Pearson（α＝0.05），n 是共享 PR 連通分量，不是 seed、順序或間隔。這個上界不是 proposal 失敗率 |
| R3-D4 | 答案鍵列出每一個合法子集與 R(S)，並標出哪些是極大。安全＝S 合法且位元組等於 R(S)。進度＝S 是否極大。接受合法但非極大的 {A} 是安全通過、進度不足。分類器 v3 實作這條，v1／v2 不改 |
| R3-D5 | 逾時時該題所有寫入者停止。晚到的提交與 ack 依 §3.2 對帳。跨專案不把分量放進同一個 bootstrap；各專案先估計，再做等權平均 |
