# ATM 0.1.28

Owner-approved patch release from main and the first release cut with the
release-PR version flow from #445. There is no runtime behavior change.

- Source manifests now carry the release version on `main`. Before this, the
  publish workflow rewrote versions only inside CI, so the committed frozen
  runner kept reporting an old development version (0.1.2 after 0.1.27
  shipped). #444 synchronized the source to 0.1.27.
- `npm run release:prepare -- --version <x.y.z>` sets every workspace manifest,
  internal dependency pin, and the lockfile in the release PR.
- `.github/workflows/release-npm.yml` now verifies that the tag matches the
  root `package.json` version and stops before any build when it does not. It
  no longer writes versions for a real tag.

Publish the annotated `v0.1.28` tag through `.github/workflows/release-npm.yml`.
The existing OIDC Trusted Publishing pipeline seals immutable CLI/starter
tarballs, verifies public npm parity, and promotes the pair to `latest`; no npm
login is required.

The previous public version is 0.1.27. This release makes no new paper result or
win claim. If promotion fails, preserve promotion receipts and reconcile only
dist-tags still pointing to the candidate, following `docs/NPM_RELEASE_PARITY.md`.
Do not republish changed bytes at the same version. Mark a defective release
known-bad before a maintainer rollback or a fresh patch release.
