# ATM 0.1.26

Owner-approved patch release from main, following the 0.1.25 process in #438.
`tasks import --metadata-only --preserve-active-claim` now also accepts a
released claim owned by the importing actor on an unfinished task, so planning
source seal drift can be repaired after the claim was released without force
import dropping amendment-only scope. Ledger validators are kept when the card
declares none. A different owner, or a done or abandoned task, is still refused.
Task and claim scopes now also cover an asset's editor companion file
(`<path>.meta`, which some editors write for every asset and folder), so a
`dir/**` scope no longer leaves the folder's own `dir.meta` behind as foreign
residue.

Publish the annotated `v0.1.26` tag through `.github/workflows/release-npm.yml`.
As in 0.1.25, that workflow bumps workspace/package versions from the tag before
building; source manifests retain the development train. The existing OIDC
Trusted Publishing pipeline seals immutable CLI/starter tarballs, verifies public
npm parity, and promotes the pair to `latest`; no npm login is required.

The previous public version is 0.1.25. This release makes no new paper result or
win claim. If promotion fails, preserve promotion receipts and reconcile only
dist-tags still pointing to the candidate, following `docs/NPM_RELEASE_PARITY.md`.
Do not republish changed bytes at the same version. Mark a defective release
known-bad before a maintainer rollback or a fresh patch release.
