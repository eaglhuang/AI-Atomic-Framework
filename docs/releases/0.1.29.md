# ATM 0.1.29

Owner-approved patch release from main. It makes upgrading an adopter's
runner a single step.

- `tasks audit` no longer requires a local transition event for a task whose
  closure belongs to another repository (`targetRepo` differs) or that is
  planning-only. A planning repository that mirrors framework task cards no
  longer reports hundreds of false `ATM_TASK_AUDIT_TRANSITION_EVENT_MISSING`
  errors (#448).
- `internal-release sync` runs the target checks (`doctor`,
  `framework-mode status`, `tasks audit`) with the previous runner and again
  with the new one. It fails only when a check that passed before fails after
  the swap, so pre-existing target problems no longer block an upgrade.
- `internal-release sync --commit` commits only `atm.mjs` and
  `.atm/runtime/pinned-runner.json` in each synced target. Other staged work in
  the target stays staged and out of that commit.

Publish the annotated `v0.1.29` tag through `.github/workflows/release-npm.yml`.
The existing OIDC Trusted Publishing pipeline seals immutable CLI/starter
tarballs, verifies public npm parity, and promotes the pair to `latest`; no npm
login is required.

The previous public version is 0.1.28. This release makes no new paper result or
win claim. If promotion fails, preserve promotion receipts and reconcile only
dist-tags still pointing to the candidate, following `docs/NPM_RELEASE_PARITY.md`.
Do not republish changed bytes at the same version. Mark a defective release
known-bad before a maintainer rollback or a fresh patch release.
