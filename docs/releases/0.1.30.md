# ATM 0.1.30

Owner-approved patch release from main. It keeps an adopter's AtomicCharter
in step with the runner and stops identity churn in tracked files.

- New `atm charter upgrade [--write] [--enforce-now]`. Framework-owned
  invariants follow the charter bundled with this release; adopter-added
  invariants and fields are preserved. Dry-run is the default, and `--write`
  records a receipt under `.atm/history/evidence/` with the previous files for
  review or rollback. A charter that is unparseable or newer than the bundled
  one is refused with `ATM_CHARTER_UPGRADE_CONFLICT` and nothing is written.
- Staged enforcement: invariants that an upgrade adds start advisory until the
  next ATM release and are rendered that way in agent skills; `--enforce-now`
  skips the window.
- `internal-release sync` upgrades the target charter with the new runner and,
  with `--commit`, commits it together with `atm.mjs` and
  `.atm/runtime/pinned-runner.json`.
- `doctor` reports an intact but older charter as the warning
  `ATM_DOCTOR_CHARTER_OUTDATED` with the upgrade command. Missing or corrupt
  charters stay errors, and the repair hint now points to `charter upgrade`
  instead of `init --force`.
- `identity set` no longer rewrites `.atm/catalog/registry/actors.json` when the
  actor record is unchanged, so re-asserting an identity on every lock or renew
  no longer leaves a dirty tracked file (#451).

Publish the annotated `v0.1.30` tag through `.github/workflows/release-npm.yml`.
The existing OIDC Trusted Publishing pipeline seals immutable CLI/starter
tarballs, verifies public npm parity, and promotes the pair to `latest`; no npm
login is required.
