When several coding agents edit the same file, admission ("these two intents do not overlap") is not the same as commit safety ("both accepted edits end up in the file exactly once, nothing else changes, and rejected proposals leave no trace"). ATM v1 (arXiv:2607.00041) made pre-write admission a first-class governance step and delegated same-file integration to a deterministic composer and a neutral steward, but did not measure whether that integration preserves all non-conflicting work. This paper turns that delegated half into (C1) a governed composition-commit protocol with explicit batch closure, late-joiner, retry and receipt semantics, and (C2) a checkable preservation contract for a restricted unified-diff subset: deterministic output, each accepted edit applied exactly once, untouched bytes preserved, and no side effects before rejection. (C3) is an empirical study of the safety/progress cost relative to strong baselines under a frozen pre-registration (HIST-v2).

What the current evidence supports is narrower. A fault-injection negative control shows that omitting the composition/commit layer loses effects at roughly the same rate as no coordination (author-reported, single host). A read-only probe of v0.1.17 exposes order dependence, exception-instead-of-receipt, and missing role checks. Six author-run validation rounds (r1–r6) on a fixed multi-process replay found and fixed a sequence of real commit-layer counterexamples (check-then-write races, per-TMPDIR locks, PID-namespace lock theft, orphan temp files, an SQLite-busy availability defect); on the final pins no lost effects or corrupted files were observed in the tested configurations. A historical real-PR workload (HIST v1.1, 300 PR pairs from six Python projects, 9,750 runs) surfaced an end-of-file-newline bug that was then fixed; however, v1.1 had three method defects (batch size always 1, non-atomic baseline commit windows, a scorer that counted skip/xfail as pass) and therefore does **not** evaluate cross-writer composition.
